# AI Agent Memory：问题驱动的技术演化与架构路线

> 第一阶段课程内容主线。范围：早期对话系统至 2026 年 11 月的主要 Agent Memory 思想、系统、评测及前沿研究。以技术问题和工程约束组织知识，而非按产品或论文逐一罗列。

## 一、贯穿全课程的核心命题

Agent Memory 的根本挑战不是“如何存储更多聊天记录”，而是：在有限计算、上下文和可信度预算下，如何将过去的交互、状态、知识和经验转化为未来决策所需要的、可访问、可更新、可验证的信息。

课程围绕一条循环展开：**新场景暴露问题 → 既有方案的边界 → 新的工程约束 → 多种技术尝试 → 实验与实践检验 → 遗留问题与新失效模式 → 下一轮设计**。

重要边界：**模型参数中的知识、当前上下文、KV Cache、会话状态、持久化执行状态、外部知识库、个人长期记忆、经验/技能记忆，不应混作同一个概念。** RAG 是可用于记忆的技术手段，不天然等于记忆系统；Checkpoint 解决恢复问题，却不等于知识更新；保存历史也不保证正确使用历史。

历史不是单一路线的替代史。长上下文、摘要、结构化状态、向量检索、知识图谱、反思、文件式记忆、技能库等路线在不同成本和任务条件下持续共存。文中使用的年代是主要研究与实践活跃期，不意味着严格的首创时间或行业统一采用时间。

## 主题 I｜Agent 记忆问题的起源（01–04）

**贯穿问题：当任务不再局限于一次对话、一个封闭流程时，传统状态管理为什么开始失灵？**

### EP01｜从任务型对话到 LLM：机器为什么总是忘记？

- **历史现场与约束**：早期任务型系统围绕订票、查询、客服等封闭任务建模；状态槽位、意图类别及可执行动作可以预先定义。开放话题、隐含偏好和新任务无法穷举。
- **尝试与技术机制**：Dialogue State Tracking、Slot Filling、POMDP 对话决策、用户画像、规则存储；对比 RNN/LSTM 隐状态与可显式检查的外部状态。
- **有效与局限**：显式槽位对可枚举任务高效、可控；任务模式一旦开放，新增状态需要改 Schema，难以承载复杂经历和通用知识。
- **导向新问题**：模型是否能够自行发现哪些信息值得成为状态与记忆？

### EP02｜LLM 到底有没有记忆？参数、上下文与外部状态的边界

- **历史现场与约束**：预训练模型掌握大量常识，但无法在普通推理调用中自动永久更新参数；上下文只对相应调用有效。
- **尝试与技术机制**：参数知识、In-context Learning、Transformer Attention、上下文窗口、KV Cache、外部持久存储；区别训练期更新与推理期读写。
- **有效与局限**：上下文学习能即时适应任务；KV Cache 可以复用注意力计算，不是可靠、可管理的跨会话事实库。
- **导向新问题**：如何在不微调权重的条件下使用新知识与用户特定信息？

### EP03｜RAG 的出现：为什么外部知识检索还不等于长期记忆？

- **历史现场与约束**：知识频繁变化，重新训练昂贵；生成模型可能编造或遗漏事实，静态知识必须由外部系统提供。
- **尝试与技术机制**：RAG、BM25、Dense Retrieval、Embedding、ANN、Chunking、Top-k；区分文档库检索与跨会话记忆的源头、时间、用户归属、更新与遗忘。
- **有效与局限**：外部检索为知识更新提供了可行工程路径；纯检索不自动回答“什么值得记”“谁授权使用”“何时不再有效”。
- **导向新问题**：Agent 产生行动与观察后，执行过程中的信息该怎样保存？

### EP04｜从 Chatbot 到 Agent：行动轨迹为何成为记忆问题？

- **历史现场与约束**：Agent 开始规划、调用工具、检查返回值、修复错误；对话文本不再等于系统全部状态。
- **尝试与技术机制**：ReAct 的 Thought/Action/Observation 轨迹；工具结果、任务进度、环境状态、计划与执行日志的不同语义。
- **有效与局限**：显式轨迹提升可追溯性和续做能力，但工具结果体积大、生命周期短、可能含不可信内容。
- **导向新问题**：当轨迹越来越长，有限上下文如何承受？

## 主题 II｜上下文管理的第一道工程难关（05–08）

**贯穿问题：信息能否被模型看到，与信息能否被模型正确使用，是两回事。**

### EP05｜为什么不能把全部历史塞进 Context？

- **历史现场与约束**：有限上下文长度、Prefill 延迟、Token 成本；长文本中有位置偏置和信息干扰。
- **尝试与技术机制**：全量历史、扩展上下文窗口、分段引用、位置布局；精读 *Lost in the Middle* 的实验设计和后续长上下文进展。
- **有效与局限**：长上下文在若干任务上减少检索需求，但不能天然处理过期事实、跨会话更新或成本；早期测试结果不可机械外推至新模型。
- **导向新问题**：能否通过裁剪和压缩，在有限预算里保留关键信息？

### EP06｜滑动窗口与递归摘要：为什么越压缩可能越失真？

- **历史现场与约束**：保留所有消息不可持续；保留最近消息又可能丢失早期关键约束。
- **尝试与技术机制**：Last-N、Token Trimming、递归摘要、层级摘要、工具输出清理、结构化任务摘要；考察压缩率、保真度和错误传播。
- **有效与局限**：窗口和摘要简单、低门槛，在许多场景仍有效；不可逆信息丢失、摘要漂移与多轮累积错误并存。
- **导向新问题**：除了压缩历史，系统能否完整恢复中断的执行状态？

### EP07｜Checkpoint 与持久化 State：恢复执行不等于长期记忆

- **历史现场与约束**：长任务存在暂停、崩溃、重试、人工介入与跨进程恢复需求。
- **尝试与技术机制**：状态机、Checkpoint、Snapshot、Event Log、Thread/Namespace、序列化、恢复、Tool Call 幂等性；对比短期状态持久化与长期可复用知识。
- **有效与局限**：Checkpoint 解决流程连续性，不能自动将一段经历转化为可迁移的知识；执行记录还需考虑一致性与敏感数据。
- **导向新问题**：谁来决定何时把哪些已保存内容放入当前上下文？

### EP08｜MemGPT：能否借鉴操作系统的分层内存？

- **历史现场与约束**：上下文被视作有限的高速工作区，外部存储容量更大但访问需要额外成本。
- **尝试与技术机制**：MemGPT 的分层记忆、Core/Recall/Archival Memory、工具调用、上下文迁移、模型控制的记忆管理；研究虚拟内存类比的成立范围。
- **有效与局限**：模型自主读写增加灵活性，带来额外调用、错误操作与控制流不可预测性；分层存储并不自动保证记忆质量。
- **导向新问题**：应该以什么形式保存长期信息，才便于未来使用？

## 主题 III｜从历史记录到长期知识（09–12）

**贯穿问题：保存过去不等于理解过去；粒度、重要性与写入决策共同决定记忆价值。**

### EP09｜Memory Stream：海量经历中如何选出相关事件？

- **历史现场与约束**：生成式角色系统要维持长期行为一致性，事件持续积累而上下文有限。
- **尝试与技术机制**：*Generative Agents* 的 Memory Stream，Recency、Relevance、Importance 评分，时间衰减与检索排序。
- **有效与局限**：在模拟交互场景展示实用价值；评分函数、权重与重要性估计依赖任务，不能视为通用最优算法。
- **导向新问题**：经历与行为记录能否提炼为更稳定、可更新的事实？

### EP10｜聊天记录、Chunk 与原子事实：记忆粒度如何改变检索？

- **历史现场与约束**：整段对话易保存却难以定点更新；过细切分又丢掉语境和因果。
- **尝试与技术机制**：Message、Session、Chunk、Atomic Fact、Event、Entity-Relation；结构化提取、来源引用和粒度对比。
- **有效与局限**：原子事实便于去重、冲突判断和精确召回；拆分错误、过度碎片化和上下文失真是代价。
- **导向新问题**：个人偏好和画像应做成统一 Profile，还是独立事实集合？

### EP11｜MemoryBank 与 Profile：长期个性化如何避免把偶然当永久？

- **历史现场与约束**：长期助手需要区分稳定偏好、当前计划、一次性要求与未经证实的推断。
- **尝试与技术机制**：MemoryBank、用户档案、重要性与时间衰减、强化记忆、结构化 Profile；研究遗忘曲线作为工程启发的局限。
- **有效与局限**：画像便于高频访问与条件过滤；静态字段难表示时间变化、例外条件与证据等级。
- **导向新问题**：能否把提取、存储、更新和召回组织成稳定的长期记忆服务？

### EP12｜Mem0 与生产化记忆：提取—更新—检索为何形成流水线？

- **历史现场与约束**：原始对话 RAG 噪声多、成本高；多轮会话需要控制存储规模和更新冲突。
- **尝试与技术机制**：Mem0 的记忆提取、候选匹配、Add/Update/Delete/No-op、检索和数据存储；对照完整历史与 RAG 基线的实验。
- **有效与局限**：明确分离写入与读取是有用的工程模式；论文的延迟、成本和准确率结果依赖基准、模型与对照设置。
- **导向新问题**：系统现在记得事实了，但能否从失败中提炼可复用的经验？

## 主题 IV｜从事实记忆到反思、经验与技能（13–16）

**贯穿问题：记忆的最高价值不在于复述事实，而在于改变后续决策。**

### EP13｜Reflection：事件很多，为什么 Agent 仍缺少高层理解？

- **历史现场与约束**：逐条观察容易产生局部、琐碎甚至矛盾的信息，难以支撑长期规划。
- **尝试与技术机制**：*Generative Agents* 的 Observation—Reflection—Planning；基于触发条件的高阶归纳，反思结果重新写入记忆。
- **有效与局限**：反思有助于抽象与行为连贯；过度泛化、错误推断和对初始偏差的强化会造成新问题。
- **导向新问题**：如果有明确任务成败，能否让反思直接改进行动？

### EP14｜Reflexion：不更新参数，能否通过失败反馈学习？

- **历史现场与约束**：每次任务失败都重新执行，低效且易重复错误；在线训练模型昂贵或不可行。
- **尝试与技术机制**：Reflexion 的执行、外部/内部反馈、语言反思和 Episodic Buffer；与梯度训练和真正的参数更新明确区分。
- **有效与局限**：在适合的任务上可改善后续尝试；错误反馈、虚假自省与跨任务迁移不足会限制泛化。
- **导向新问题**：反思是文字建议，能否将成功操作变成可再次调用的技能？

### EP15｜Voyager：为何可执行 Skill Library 是另一类记忆？

- **历史现场与约束**：Agent 重复解决相似子任务，文本经验难保证执行过程稳定复现。
- **尝试与技术机制**：Voyager 的自动课程、代码形式技能库、技能检索、执行反馈和修正；对比文本经验与可执行程序。
- **有效与局限**：技能复用改善组合任务效率；环境变化、依赖失效、错误技能积累和安全验证仍是障碍。
- **导向新问题**：如何持续整理越来越多的经验和技能而不退化？

### EP16｜ACE：反复重写经验为什么会发生 Context Collapse？

- **历史现场与约束**：一次次总结或整体重写 Playbook 可能丢掉细节、强化片面经验。
- **尝试与技术机制**：Agentic Context Engineering 的 Playbook、Generation、Reflection、Curation，增量编辑与整体重写的比较。
- **有效与局限**：渐进维护有机会减少经验丢失；同样可能积累重复条目、错误规则和维护成本。
- **导向新问题**：写入何种经验、何时写入，必须成为显式的工程决策。

## 主题 V｜Memory Write：选择、建模、更新与写入时机（17–20）

**贯穿问题：错误记忆一旦写入，检索再精良也可能只是在高效传播错误。**

### EP17｜记忆准入：为什么不能看到信息就写入？

- **问题约束**：记忆价值未知且具有未来性；严格筛选会漏记，宽松存储会稀释相关信息。
- **技术路线**：显式用户指令、规则式准入、Salience/Novelty/Utility 评分、LLM Write Gate、反馈驱动写入。
- **有效与局限**：可解释规则适合明确政策；模型判断灵活但容易误把显著性当长期价值。需要讨论 Write Precision/Recall 和误写成本。
- **新问题**：既然要写，如何保证类别、粒度、来源和置信度正确？

### EP18｜抽取与 Schema：事实、事件、偏好、推断如何分开？

- **问题约束**：自然语言混合时态、主张、意图、假设、否定和多实体关系。
- **技术路线**：信息抽取、Entity/Relation Extraction、结构化输出、Schema 校验、事实与推断分层、Provenance、Confidence。
- **有效与局限**：Schema 使检索和治理可控；过硬的 Schema 丧失灵活性，模型抽取错误会在结构化后更难察觉。
- **新问题**：新事实与旧记忆相似、重复或冲突时怎么办？

### EP19｜记忆增量维护：Add、Update、Delete 与 No-op 如何决定？

- **问题约束**：事实重复、用户改变偏好、时间状态变化、并发写入和旧记忆仍可被召回。
- **技术路线**：候选匹配、语义去重、冲突检测、Patch、覆盖与追加、Versioning、事务与幂等。
- **有效与局限**：覆盖便于读取最新状态，追加便于审计历史；混合策略增加复杂度但能保留时间语义。
- **新问题**：每轮都同步执行复杂写入，会否拖慢交互？

### EP20｜热路径与后台整理：记忆写入应在什么时候发生？

- **问题约束**：响应延迟、成本、批处理效率、跨会话可见性、重试与并发一致性。
- **技术路线**：同步写入、异步队列、Session-end Consolidation、定时维护、事件触发与主动工具调用；可靠投递和可重放事件。
- **有效与局限**：异步优化热路径但带来最终一致性；同步易控制但放大延迟；应按场景选择而非统一规定。
- **新问题**：记忆写得再好，也必须在正确时刻被正确召回。

## 主题 VI｜Memory Read：从检索到决策可用的上下文（21–24）

**贯穿问题：记忆检索的目标不是找“语义相似的句子”，而是提供当前行动所需要的可信证据。**

### EP21｜向量检索为什么既重要又不够？

- **问题约束**：用户问题可能包含精确实体、数字、否定、时间和特定项目范围；向量相似度不总能保持这些区别。
- **技术路线**：BM25、Dense Embedding、ANN、Hybrid Retrieval、Metadata Filter、不同索引粒度；对比性能与索引成本。
- **有效与局限**：混合检索通常具备较稳健的候选召回空间，但参数、重排序与数据分布决定收益。
- **新问题**：用户提问可能连足够的检索关键词都没有。

### EP22｜Query Understanding：如何知道 Agent 究竟要回忆什么？

- **问题约束**：省略、代词、跨会话实体、时间指代、多跳问题会导致原始查询不完整。
- **技术路线**：Query Rewriting/Expansion、Entity Resolution、Temporal Query、Fact-augmented Index、多阶段检索；结合 LongMemEval 的研究。
- **有效与局限**：补全查询可提升检索，过度改写却可能注入不存在的实体或假设。
- **新问题**：找到多个候选以后，如何决定优先级、可信度与上下文预算？

### EP23｜Reranking 与 Context Packing：召回正确为何仍可能回答错误？

- **问题约束**：候选包含冗余、冲突、过期信息；模型对信息顺序与噪声敏感。
- **技术路线**：Cross-Encoder/LLM Rerank、MMR、时间与来源加权、冲突组装、证据充分性检验、Token Budget Packing。
- **有效与局限**：重排和证据选择可改善有效利用率，增加额外调用与延迟；相关性不等于真实性。
- **新问题**：是否每一轮都值得支付检索成本？

### EP24｜主动与被动回忆：该由框架还是 Agent 触发检索？

- **问题约束**：Always-on 易制造噪声；Tool-driven 灵活但存在漏查、过度搜索和不可预测成本。
- **技术路线**：固定 Top-k、规则触发、条件检索、主动 Memory Tool、两阶段检索与检索控制器。
- **有效与局限**：在信息依赖高的任务中检索有利；在当前上下文已充分时，“不检索”也应是合法且可评测的选择。
- **新问题**：即使召回正确，事实可能已经变化，历史与当前状态如何区分？

## 主题 VII｜Memory Evolution：时间、一致性与混合架构（25–28）

**贯穿问题：长期记忆必须允许世界变化，否则忠实记录过去会伤害当下决策。**

### EP25｜时序与有效性：为什么曾经正确不等于现在正确？

- **问题约束**：项目职责、关系、偏好会变化；用户需要查询过去与现在两种状态。
- **技术路线**：Valid Time、Transaction Time、Bitemporal、Event Sourcing、Fact Invalidation；Zep/Graphiti 的 Temporal Knowledge Graph。
- **有效与局限**：时间数据能支持历史追问和状态更新，换来构图、事实合并和查询复杂度。
- **新问题**：事实不只沿时间变化，还存在关联网络；如何组织这种联系？

### EP26｜A-MEM：记忆为什么要形成可维护的关联网络？

- **问题约束**：大量孤立事实在推理时难被联结，直接全量重写则昂贵且易失真。
- **技术路线**：A-MEM、Zettelkasten 风格笔记、标签、动态链接、记忆属性演化；与知识图谱和相似性网络对比。
- **有效与局限**：动态关联提供新的组织方法；错误链接和联动修改可能带来级联污染。
- **新问题**：关联越丰富，存储与推理成本也越高，如何整理和遗忘？

### EP27｜Consolidation 与 Forgetting：为什么记忆越多不一定越强？

- **问题约束**：重复、低价值、过期和噪声记忆不断积累；删除又可能损害历史追溯。
- **技术路线**：去重、聚类、层级摘要、TTL、时间衰减、使用频率、Utility-based Retention、归档与软删除。
- **有效与局限**：定期整理能降低成本，但过早合并和删除会破坏例外、时间事实及审计链。
- **新问题**：单一种类的存储难满足所有能力，是否需要组合架构？

### EP28｜Hybrid Memory：为什么文件、Profile、Event、Vector 与 Graph 长期共存？

- **问题约束**：低延迟、精确事实、语义搜索、关系/时间推理、权限隔离和可维护性相互牵制。
- **技术路线**：Profile Store、Event Store、Vector Index、Graph Index、文件式记忆、分层存储与路由；比较 LangGraph、Letta、Mem0、Zep/Graphiti。
- **有效与局限**：混合架构可能适配异质查询，但复制、索引同步、数据权威来源和迁移增加系统责任。
- **新问题**：如何用可信实验判断架构复杂度的收益是否真实存在？

## 主题 VIII｜Evaluation、Security 与 Governance（29–32）

**贯穿问题：一个看起来有效的记忆 Demo 与一个真正可靠的长期系统之间，差的是可复验的证据。**

### EP29｜LoCoMo、LongMemEval、MemoryAgentBench：记忆基准究竟测到了什么？

- **问题约束**：长期对话记忆、时间推理、跨会话检索、交互式更新与真实任务效果不是同一类能力。
- **技术路线**：研究各基准构造、标注、任务类型、评价方法、数据污染与任务覆盖；区分静态 QA 和执行型任务。
- **有效与局限**：基准使比较成为可能，但分数未必解释真实生产中写入冲突、权限或行动收益。
- **新问题**：如何排除底层模型、Token 预算和 Judge 偏差造成的虚假性能提升？

### EP30｜Memory Evaluation：怎样证明记忆带来了真实的因果收益？

- **问题约束**：更大模型、更多上下文、更强检索器可能掩盖某个记忆模块的实际贡献。
- **技术路线**：无记忆、全历史、原始日志 RAG、结构化/混合记忆等强基线；Ablation、Equal-budget、Counterfactual Replay、Oracle Write/Retrieve、LLM Judge 校准。
- **有效与局限**：分层指标比单一 QA 正确率更有解释力；评测需要同时测写入、检索、时间一致性、任务成功、成本和延迟。
- **新问题**：即使改善了成功率，错误或恶意记忆是否会形成持久安全风险？

### EP31｜Memory Poisoning：一次不可信输入如何形成长期攻击？

- **问题约束**：工具输出、网页、对话内容可能包含恶意指令；一旦写入长期记忆，之后会被重新注入高信任上下文。
- **技术路线**：Prompt Injection、Memory Poisoning、Retrieval Poisoning、信任边界、来源追踪、写入/检索双重验证、清除污染；研究 AgentPoison、MINJA、MemoryGraft 等案例。
- **有效与局限**：来源与权限治理能降低风险，不存在仅凭一句“忽略恶意指令”就保证安全的解决方案。
- **新问题**：除了恶意攻击，跨用户隔离、删除、缓存与备份都影响长期可控性。

### EP32｜生产治理：可删除、可追溯、可隔离的记忆是什么样？

- **问题约束**：多租户、多项目、并发写入、隐私与保留期限使长期记忆成为数据治理问题。
- **技术路线**：Owner/Namespace、RBAC/ABAC、Encryption、Retention、审计、Rollback、删除传播、派生索引失效、备份生命周期、可观测性。
- **有效与局限**：数据存储权限与模型执行权限需分离；“删除一条原始记录”不等于所有派生摘要和索引都已删除。
- **新问题**：当一个 Agent 的记忆可治理后，能否将经验跨 Agent、跨环境共享与迁移？

## 主题 IX｜前沿：技能积累、多 Agent、多模态与自主记忆（33–36）

**贯穿问题：记忆系统能否从被动记录与检索，发展为能够持续验证、学习和调整记忆策略的基础设施？**

### EP33｜从轨迹到可验证技能：成功执行如何转化为可复用能力？

- **前沿问题与约束**：成功轨迹不必然形成可迁移技能；执行依赖环境、工具版本与前提条件。
- **技术路线**：Verified Traces、Skill Extraction/Compilation、Reflector/Curator、Skill Versioning、Outcome-based Validation；连接 Voyager 与 2025–2026 年技能整理工作。
- **有效与局限**：可执行技能具有明确复用价值，但成功样本偏差、跨环境失效及技能安全尚需验证；应区分研究原型与成熟生产实践。
- **新问题**：单 Agent 技能可积累，跨 Agent 的共享经验是否仍保持有效？

### EP34｜Multi-Agent Memory：为什么共享数据库不是共享记忆的全部？

- **前沿问题与约束**：多个 Agent 具有不同目标、权限、观察范围和可信度；并发修改会导致版本冲突。
- **技术路线**：Private/Shared/Team Memory、Blackboard、共享事件日志、所有权、协作证据传播、冲突合并与权限策略。
- **有效与局限**：共享记忆可减少重复劳动，却增加污染扩散、责任归属和一致性难题。
- **新问题**：当观察来自图像、声音或物理环境，文字与结构化记忆是否足够？

### EP35｜多模态与神经记忆：外部文本存储是否会遇到天花板？

- **前沿问题与约束**：持续感知、空间关系、物体追踪和隐式状态难被简单文字完整表达。
- **技术路线**：多模态/具身事件记忆、视觉与空间索引、原始证据与文本摘要融合；另一条线研究 Recurrent/Latent/Test-time Memory、Titans 等内部记忆机制。
- **有效与局限**：隐式神经记忆与显式外部记忆面向不同可解释性、编辑、存储及删除约束；不能把两者作为简单替代。
- **新问题**：存储形式多样化后，记忆管理策略本身能否适应环境与任务？

### EP36｜Self-Evolving Memory：Agent 能否学会如何记忆？

- **前沿问题与约束**：固定的 Write Gate、检索触发与遗忘规则难适配所有场景；但优化长期收益存在信用分配和反馈噪声问题。
- **技术路线**：Memory Controller、Dynamic Policy、Meta-Memory、反馈驱动策略调整、RL/长期信用分配、分层显式与隐式记忆。
- **有效与局限**：自适应控制具有潜力，却增加探索成本、回归风险和不可预测性；需要与固定策略公平比较。
- **最终开放问题**：通用 Agent Memory 会收敛为统一架构，还是持续维持“运行时状态 + 事实 + 时间 + 经验技能 + 权限治理 + 自适应控制器”的组合系统？

## 三、贯穿各主题的十组技术争议

以下都是**待限定条件、待检验证据的命题**，并非一律被证实失败的方案。

| 工程假设 | 关键反例或边界 | 对应期数 |
|---|---|---|
| 上下文足够长就无需记忆 | 成本、信息干扰、时间更新与可控删除 | 05、06、30 |
| 反复摘要可无限延续工作 | 信息不可逆丢失、摘要漂移 | 06、16、27 |
| 保存全部历史并做向量检索就够 | 精确实体、时间、否定、更新与关系查询 | 10、21、22、25 |
| 类人遗忘曲线必然更好 | 心理学类比不是工程性能证明 | 11、27 |
| 让模型自己判断重要性即可 | 显著性、真实性与长期任务效用不同 | 17、18、30 |
| 反思会稳定促进自我改进 | 反馈误差和自我强化偏差 | 13、14、16 |
| 图谱天然优于向量检索 | 构图、维护、查询类型与一致性成本 | 25、26、28 |
| 成功轨迹可直接变为可靠技能 | 偶然成功、环境依赖、验证不足 | 15、33 |
| 记忆越多 Agent 越好 | 冗余、误召回、错误传播与成本 | 24、27、30 |
| 自主管理总优于固定规则 | 不确定性、额外调用、控制与安全成本 | 08、20、36 |

## 五、课程结束时的架构判断框架

面对任意 Agent 业务需求，最终需要有能力判断：

1. 需求究竟是跨步骤的 **State Recovery**、跨会话的 **Knowledge Memory**，还是跨任务的 **Experience/Skill Memory**？
2. 记忆在哪里产生、由谁授权，哪些信息必须禁止写入？
3. 应采用怎样的存储粒度、Schema、时间模型与权威数据源？
4. 读写发生在什么时机，如何兼顾准确率、延迟、成本与一致性？
5. 记忆如何覆盖、归档、遗忘、删除，以及如何验证这种变化已传播到索引和上下文？
6. 如果采用图谱、长上下文、反思或自主演化，它们的收益是否优于更简单的强基线？
7. 哪些结论有重复实验支持，哪些只是特定场景有效，哪些仍处于前沿探索？

**课程的终点不是一种“最先进的记忆技术”，而是根据约束构造、论证并验证记忆架构的判断能力。**
