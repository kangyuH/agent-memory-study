## [Q01] 早期有界任务如何规定输入、状态与动作

ATIS 1990 试点以自发口语向固定的 OAG 关系数据库查询航班信息，采集时分配旅行任务，明确数据库缺少酒店、租车等信息。语言表达可以多变，问题的可回答性和后端事实却被语料设计约束。这里的“有界”描述业务接口和目标集合，并允许自然语言输入超出设计者预写的句式。[C01]

PEGASUS 1994 实际接入 EAASY SABRE。语音理解输出语义框架，System Manager 把它转换成既有后端命令，信息不足时发起澄清，收到后端响应后解析表与菜单项、临时保存候选，再进行过滤和展示。尝试预订之前还检查航班可用性。原文报告了应用层筛选条件，例如下午起飞。框架、后端语义、候选结果和待确认动作分别承担职责。[C02]

| 代表材料 | 改变的主要环节 | 系统边界 |
| --- | --- | --- |
| ATIS、PEGASUS [C01] [C02] | 固定数据或操作接口内的语义框架、澄清和业务映射 | 领域实体与后端接口明确定义 |
| DSTC2 focus、Williams–Young POMDP [C05] [C08] [C10] | 用置信质量累计证据，或维护分布并以长期回报选择动作 | 候选、转移、观测与收益由任务模型约束 |
| 词级 RNN DST [C15] | 从词特征学习更新，保留显式输出与内部递推 | 沿用槽位和概率输出契约 |
| SGD [C21] | 用随服务提供的描述接入动态意图与槽集合 | 服务 Schema 仍由外部提供 |

这个样本支持规则、概率估计和神经计算可以在同一个系统的不同接口共存。这里给出的时间线对应取到的代表材料，不能据此判定产业采用顺序或技术首创。[C03] [C15]

## [Q02] 意图、槽填充、状态跟踪和策略的观测边界

意图识别或语义解析刻画当前用户表达。槽填充输出当前可识别的参数或约束。DST 把这一步的结果、已知历史以及系统的问法转为持续状态。对话策略再消费这个状态，选择澄清、确认、查询或执行。实际系统可以联合建模。上述接口主要用来标出可对照的输入与输出。[C02] [C03] [C04] [C08]

DSTC2 把状态分为目标约束、请求字段、搜索方式。地点或价位属于目标约束，所询问的电话或地址属于请求字段，按现有条件查询或索要备选属于搜索方式。SGD 的状态另有活跃意图，并按服务描述理解字段。两个任务中同名的状态概念应和各自标注说明一起使用。[C04] [C06]

| 现象 | 最少应查看的材料 | 能归属的阶段 |
| --- | --- | --- |
| 新信息从未进入结构化输入 | 原话、语音识别候选、语义解析和置信度 | 观测或提取 |
| 结构化输入有纠正，状态仍保持旧值 | 更新前状态、新候选、动作和更新后状态 | 跟踪与更新 |
| 状态正确，业务参数仍不正确 | 策略实际读入、选择动作、参数和后端反馈 | 状态采用或行动 |
| 新会话无法取用此前信息 | 用户键、有效性、持久化记录、读取路径和后续输入 | 跨会话续存 |

这张表是基于系统接口的诊断归纳。离线 DST 只观察它定义的状态输出。样例中修订金标也可以使同一个预测的评估结果变化，见 Q11。[C03] [C16] [C23] [C34]

## [Q03] 显式状态如何按回合更新与纠正

DSTC2 允许目标在对话中变化。语义假设可同时支持多个候选。作者手册 S19 §5.1 的 focus 把加权旧信念与本轮槽值 SLU 证据相加。目标和方式的旧项系数为 1 减本轮证据总质量，无新证据则保持旧状态，证据量为 1 则采用本轮分布；系统告知所请求字段时可以重置相应分数。S03 §3.2 的刊载系数写成证据和，本期资料按两份原文分列。复盘需要同时检查当轮假设和上一轮信念。词级 RNN 跟踪器将同类更新交给训练得到的模型，其输入仍包含先前显式分布。[C04] [C05] [C15]

| 状态或操作 | 在所查实现中的定义 | 证据边界 |
| --- | --- | --- |
| 不更新旧值 | SGD 的槽状态 none 保持已有目标字段 | 来源支持该实现，其他标注契约可能有不同编码 [C06] |
| 明示任意值 | SGD 的 dontcare 写入无偏好 | 与系统还不知道字段取值的情况需要分别记录 [C06] |
| 新值或纠正 | SGD 的 active 选择类别候选或找文本跨度；Diable 的 INSERT 可覆盖既有槽 | 纠正成功依赖输入能表达目标值，并依赖更新解释器 [C06] [C07] |
| 清除约束 | Diable 表操作有 DELETE；无操作序列用字面量 none | none 的含义跟着协议走；不同协议的未给定值须单独理解 [C07] |
| 竞争候选 | focus 和词级 RNN 以分布保留多个值；TRADE 可按槽生成或复制文本值 | 分布、文本值和当前选择的业务动作是不同输出 [C05] [C15] [C19] |

Diable 的差分写入可以减少重复生成，但前一预测状态会参与下一次更新，错误可能持续。作者用金标前状态做独立诊断，不能用这一条件代替实际运行的得分。完整输入历史与差分输出可以同时存在，两项设计需要分别控制。[C07] [C18]

## [Q04] POMDP 信念、澄清动作与可扩展性

Williams 与 Young 把用户目标等因素置于不可直接观察的状态。系统执行动作后获得观测，用旧信念与转移模型预测下一状态，再用观测似然加权和归一化。策略把信念映射成动作，并按预先定义的收益选择操作。完整计算式和变量见 [技术笔记](technical_notes.md)。[C08]

在原文语音信箱示例中，删除有用消息和保留不想要的消息具有不同代价，询问也有成本。§2.1 的动作只有 ask、doSave、doDelete。该例的低置信区域选择 ask，高置信区域可执行保存或删除，分区受收益与观测模型约束。§4.1 的旅行任务仿真另有 confirm 等动作，原文也另外规定了提前确认的代价。两组设定的回报及其动作空间分别记录，生产环境的真实用户成功率也另有口径。[C09]

状态集合、动作和观测的规模随候选增加。作者用用户目标、用户动作和对话历史等因子描述概率模型，并讨论 Summary POMDP，将规划放在压缩空间并与信念监控区分。归纳时需要保留任务结构、近似假设和求解预算。压缩策略能否移植到另一个领域，需要重新检查目标、动作、数据和实际损失。[C10]

## [Q05] 规则、持久用户画像、当前约束和领域知识

MATCH 的注册问卷让用户在餐厅属性上给出排名和部分偏好，系统转成权重与偏好值，保存在持久数据库。推荐与对比根据这些权重及候选属性计算效用。独立的任务模型提供用户无关的选餐厅目标属性树。该证据直接支持以外部画像参与响应生成；任意用户对话里隐含偏好的自动发现、一次性例外归并和过期规则，需要另找证据。[C11]

PEGASUS 暂存航班表和可选操作，是当前业务任务需要的工作记录。ATIS/OAG 和业务后端的航班属性属于服务事实。两类状态都可以被后续读取，但身份键、写入者与有效期不同。PEGASUS 的短撤销规则能恢复前一对话状态，涉及预订时要求向 SABRE 发取消请求；清空对话历史是另一项操作。已有失败日志展示二者的区别，见 Q11。[C01] [C02] [C12] [C38]

**研究归纳。** 同一属性可同时拥有用户默认值和当前任务约束，应登记原始出处、对象、有效时间、作用域及覆盖来源。例外是否过期、何时写回用户默认、如何处理矛盾信息由系统明确约定。现有材料支持分设数据接口，未给适用于所有场景的优先级或保存时长。多会话预测摘要和基于问答奖励的写入是另外两种取证对象，见 Q09–Q10。[C12] [C30] [C32]

## [Q06] RNN/LSTM 隐状态、显式状态和混合接口

LSTM 有可定位的 1995 年技术报告。本资料采用的 1997 年期刊版本用输入门、输出门与内部单元的自循环处理长时滞的学习问题。Gers 等后续工作引入可学习的遗忘门，用于连续输入时对旧单元状态进行衰减或重置。这里的旧状态是模型内部数值；实现能够保留、重放或清空这一向量，跨会话持久化取决于整个系统的边界。[C13] [C14] [C34]

Henderson 等的词级 RNN DST 是可复查的混合例子。当前 ASR 或 SLU 及系统话轮特征、上一轮显式槽值概率和内部向量参与下一轮计算。标记与未标记特征分支的输出形成下一轮显式分布，内部向量另做 logistic 递推。模型使用前一显式分布与隐向量来继续跟踪。接口可查询槽分布；内部向量编码的具体语义需要其他证据。[C15]

focus 在显式概率上使用人工更新规则。Diable 在显式表上使用模型预测操作。TRADE 以神经生成器预测显式域槽值三元组。由这些实例可以把三件事分别比较：用规则或模型估计更新、对外使用分布还是值表、服务边界怎样重置或保留状态。结果说明这些设计维度可组合。若只保存能展示的字段，隐藏递推或状态更新所需信息仍可能缺失。[C05] [C07] [C15] [C19]

## [Q07] 封闭领域实证、运行成本和可控性

DSTC2 用相同餐馆对话测试日志重放跟踪器，训练和测试的对话管理条件有差异。联合目标准确率考查整组约束是否匹配，L2 比较概率输出与标注，值较低更好。请求字段和搜索方式另列指标。相同日志控制了部分变量，输入通道、模型集成和推理开销仍可不同。[C16] [C17]

| h-SLU | 0.742 | 0.387 | SLU 输入，上游使用词混淆网络，S08 Table 2 |

两项 RNN 提交各集成 12 个跟踪器。上述表格未报告这三组的成对显著性或统一推理成本。S03 Table 4 的统计检验针对另列的集成对照。S08 在实现说明中另报告，每状态组件使用一个 RNN 的未优化 Python 跟踪器，在 3.2 GHz Intel Core i7-970 上约每秒处理 50 回合。这是独立配置下的跟踪吞吐量；集成提交的准确率、语音前端和端到端响应速度需要另测。[C17] [C36]

PEGASUS 的预订前检查是可观察的操作约束。作者还报告一组初步实际任务结果。8 名研究组成员用系统处理 10 次真实往返订票，7 次完成；Table 1 的成功订票均值为 24.5 次查询和 814 秒，正文记有 6 位成功参与者。耗时与查询数针对成功样本，样本小且没有随机对照。现场结果、错误日志和端到端耗时与离线状态准确率分开阅读。[C37] [C38]

DSTC2 测量状态匹配，TRADE 与 IC-DST 的数值属于不同 MultiWOZ 设置，MSC 与 Memory-R1 又使用语言生成或问答指标。已核验的这组对照没有在共同协议中统一测量整个系统的任务成功、风险和运行成本。[C02] [C16] [C20] [C25] [C31] [C33]

## [Q09] 给定 Schema 跟踪、发现新类别、选择长期信息

**给定 Schema 的 LLM 跟踪。** IC-DST 把任务写成 SQL 形式，给模型表结构和任务说明，少样本条件再检索标注示例。Codex-davinci 在 1% 示例池下，MultiWOZ 2.1 和 2.4 的 JGA 分别是 43.13 和 48.35。1% 说明可检索示例池的规模口径，每个提示的示例条数另行设定。论文中 Codex 用 10 个、GPT-Neo 用 5 个。这个结果支持给定结构下的提取与更新；由于 Schema 由实验者提供，应单独看类别发现的证据。[C24] [C25]

**发现候选类别。** GenDSI 对对话生成槽名和值，再聚类评估。S13 Table 2 的 MultiWOZ 2.1 验证集，GenDSI 的槽 F1 90.9、值 F1 70.5，诱导槽 180 个，参考为 31 个。Table 2 的主 GenDSI 行使用剔除与 MultiWOZ 和 SGD 旅行相关领域重叠的 34 个领域后剩余的 D0T 对话训练。该评价容许多个聚类匹配同一参考槽。USI 在同表槽 F1 更高、值 F1 更低。状态推断另用 S13 Table 1 的人工评价，从 D0T 和 SGD 各取 60 条未见域话轮，每条来自不同对话。在 D0T 测试中，T5-SGD 的完整性/正确性为 32.3%/72.6%，GPT-D0T 为 93.3%/82.0%，T5-D0T 为 95.7%/81.2%。T5-D0T 在 D0T 的非测试域训练，T5-SGD 由 SGD 训练。原表用 Agresti–Caffo 检验标注列内对照（p < 0.05）。保留训练分布、指标和标注条件。流式工作另用模拟互动生成新领域资料和经人修订的测试数据，也允许用最终 Schema 回放早期回合。[C26] [C27] [C28]

S14 Table 6 在 DOTS 测试上提供同底座、训练数据标记为 DOTS 且状态表示为 FINAL 的比较。Embed、Revision、Slot Conf 的槽/值 F1 分别为 46.2/74.8、57.8/68.2、66.8/74.9。Revision 的槽 F1 高于 Embed，值 F1 则更低。各指标对 10 个测试场景分别评估后取均值，并对 3 次重复取均值。S14 §5.2 的映射以大小写无关的精确值匹配计算相似度，阈值为 0.5，精确率将冗余槽预测计为错误。S13 的匹配与计数规则不同，保留各自的分数口径。业务操作和长期收益另需实证。[C40]

**公开基准已有知识的对照。** S14 Table 2 的 GPT-4o 只见数据集名称、未见该样本的对话，复述 MultiWOZ 槽的 F1 为 100.0，SGD 为 63.0。能凭名称复述的结果意味着公开基准上的高分需要与对照一起阅读。该实验无法追溯训练数据究竟包含哪一份材料，也无法说明所有模型都同样受影响。[C29]
