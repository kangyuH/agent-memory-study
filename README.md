# Agent Memory Study

本仓库维护 AI Agent Memory 的 36 期研究大纲与一套可复用的 Codex Skill。Skill 以课程大纲为输入，逐期设计研究问题、核验一手来源、整理概念和技术证据，并审核覆盖范围与准确性。研究资料可供 NotebookLM 使用，面向听众的解释由 NotebookLM 负责。

## 项目进度

课程大纲和设计任务书已入库。仓库提供 [Skill 设计](docs/skill-design.md) 与 [实现入口](.agents/skills/agent-memory-research/SKILL.md)。

| 顺序 | 阶段 | 完成条件 |
| --- | --- | --- |
| 1 | Skill 设计 | 明确入口与参数、目录与数据契约、阶段状态及失败恢复、脚本与模型的分工、独立审核方式。核实可用工具与权限，写清验收门槛和测试计划。 |
| 2 | EP01 单期试点 | 用 EP01「从任务型对话到 LLM」跑通章节解析、一手来源核验、问题与证据映射、资料汇总、独立复核和覆盖验收。保留输入版本、产物及验收报告。 |
| 3 | 测试与修订 | 在 EP01 基础上再选择至少两类不同的章节做端到端验证，例如 EP08（系统架构）和 EP29（评测比较）。抽查证据账本，验证伪造引用、缺失来源、跨期冲突、断点恢复、重复运行和恶意来源等场景。 |
| 4 | 批量运行与复用 | 按知识依赖运行多期，检查跨期术语与结论的一致性，验证来源刷新与替换课程大纲后的运行效果。 |
| 5 | 使用与交付说明 | 记录运行方式、参数、前提、恢复流程、产物、审核机制、测试结论和已知限制。 |

## 跟踪与验收

- GitHub Issue 用于跟踪一个可验收的工作单元，例如设计、试点或跨期缺陷。描述写清交付物、完成条件和依赖，有阻塞时记录原因和解除条件。
- PR 关联对应的 Issue，并附上验证结果或验收报告。课程范围或分期需要调整时，在 PR 中列出受影响的期数和依赖。
- 单期以验收报告为准。核心主张要能追溯到可定位的一手来源，独立审核要逐项核查问题、证据、反例和条件。必要问题已覆盖、硬性门槛通过且所有阻塞项解决后，才标记为 `ACCEPTED`。
